# Trifoss Website

Static site for Trifoss. See `Architecture.md` in this repo for the full system design, scope, and risks.

## Structure

```
index.html                  Homepage — all sections in one page, anchor-linked.
                             Events/News/Gallery tiles are regenerated by the
                             build script between <!-- BUILD:...:START/END -->
                             marker comments — edit outside those, not inside.
privacy-policy.html         Privacy policy
content-policy.html         Submission content policy (linked from Events/News forms)
assets/
  css/styles.css            Design tokens + all styling
  js/main.js                Mobile nav toggle + photo gallery lightbox
  images/                   logo.svg, favicon.svg (placeholders — replace with real logo)
                             events/, news/ — generated event/article images land here
events/
  past-events.html          Past Events archive — fully regenerated by the build script each run
  <slug>.html                Generated event pages (one per approved event)
news/
  archive.html              News Archive — fully regenerated by the build script each run
  <slug>.html                Generated article pages (one per approved article)
scripts/build.js            The real build script — see its header comment for what it does
.github/workflows/          GitHub Actions workflow (currently manual-trigger only; see comments)
```

## How content actually gets published (once live)

Events and News & Blogs share a **two-stage** moderation pipeline: each content type has a Stage 1 and a Stage 2 Google Sheet, shared only with the relevant moderator(s), with a handoff script copying an item to Stage 2 only after Stage 1 approves it. The hourly build reads only from Stage 2. Membership sign-up is reviewed separately, **single-stage**, via an Approvers Sheet with one-click approve/reject email links; approval triggers a payment link, and membership only becomes Active once payment is confirmed via webhook. Every donation and membership payment is logged to one shared Payments Sheet by the same webhook. Newsletter signups stay on a Google Form for consistency but are synced to Mailchimp, which does the actual sending. See `Architecture.md` for the full picture.

## Build pipeline setup (one-time)

The build script reads approved Events/News from a small Apps Script Web App (it can't call the Google Sheets API directly with no credentials of its own). To wire this up:

1. In the same Apps Script project as the rest of the automation, paste in `build_data_webapp.gs` (ask Claude for it if you don't have a copy) and run `generateAndStoreSecret` once — copy the secret it logs.
2. Deploy it: **Deploy → New deployment → Web app**, with **Execute as: Me** and **Who has access: Anyone**. Copy the resulting Web app URL.
3. In this GitHub repo: **Settings → Secrets and variables → Actions → New repository secret**, twice:
   - `BUILD_ENDPOINT_URL` = the Web app URL from step 2
   - `BUILD_ENDPOINT_KEY` = the secret from step 1
4. Trigger a test run from the **Actions** tab → "Build and publish site" → **Run workflow**, and check the result before ever enabling the hourly schedule (commented out in `.github/workflows/build.yml`).

If you edit `build_data_webapp.gs` later, you must redeploy (**Deploy → Manage deployments → pencil icon → New version**) — editing the code alone doesn't update what's already live.

## How to preview locally

Just open `index.html` in a browser — no build step required for the current scaffold.

## How this gets published

Once GitHub Pages is turned on for this repo (Settings → Pages → deploy from the `main` branch), the site becomes publicly reachable at the GitHub Pages URL, and later at the custom domain once DNS is pointed at it.
